# RimWorld Save Inspector v1.0.0 implementation plan

> For agentic workers: use subagent-driven-development for bounded tasks, or executing-plans for lead-owned integration. Beads owns task state; the numbered items below define deliverables rather than a second task tracker.

**Goal:** Deliver all specified read-only interfaces as a coherent, independently accepted v1.0.0 package and safely publish its repository and tagged release.

**Architecture:** Retain one streaming parser, immutable snapshot, typed indexes and shared query service behind Python, JSON CLI and stdio MCP. Correct serialized-state semantics at the shared boundary, then prove transport equivalence and downstream consequences. Public verification uses synthetic fixtures; private acceptance remains local.

**Tech stack:** Python >=3.11, defusedxml, Pydantic, optional official MCP SDK, pytest, Draft 2020-12 JSON schemas, Hatchling/uv, GitHub Actions.

**Spec:** docs/design.md and docs/rimworld-save-inspector/; current user v1 release objective supersedes the historical implementation-only authorization language.

## Global constraints

- Original saves remain unchanged. Destructive fault injection uses disposable synthetic files or copies.
- Required domains: summary, pawn core/skills/traits, health, both gene groups, equipment/apparel, inventory/nested holders, research/techprints and mods.
- Preserve schema v1 population bases, unknown versus zero, raw numeric lexemes, duplicate records, typed reference uncertainty and provenance.
- CLI and Python invocation snapshots are immutable; one MCP process pins one immutable snapshot, refreshed only by restart.
- No runtime network, save writes, arbitrary source tool parameter or mutation interface.
- Python 3.11 and 3.14; macOS arm64 and Linux x86_64 acceptance. Best-effort game versions remain explicitly qualified.
- Pass final packaged G0–G7, public synthetic CI, independent oracle comparisons and fresh reviewer reproductions. Preserve failed attempts and rerun affected evidence after changes.
- Do not publish private oracle values, saves, extracted records, credentials or machine-specific paths. Exact baseline history is preserved privately while the detected history/privacy contradiction awaits explicit user resolution.
- Lead owns architecture, integration, acceptance and release. Specialists own only assigned files. Policy v2026.09.26.1.

## Review focus

1. A pawn's core counts must agree with its serialized immediate child entries; unavailable collections yield null, and reference entries count without multiplying unique item units.
2. An unrelated off-map or nested collection cannot change a direct-map roster's availability or totals.
3. An unavailable collection cannot return ordinary entries with an unknown total or silently discard valid siblings without diagnostics.
4. Pagination, default selectors, duplicate identities and nested ownership must not produce double counting, mixed snapshots or misleading certainty across interfaces.
5. Failure/cancellation/concurrent loads cannot publish half-built state, leak source paths or leave owned workers alive; a clean archive is not proof of clean Git history.

## Task 1 — independently reproduce and repair downstream semantics

Files: src/rimworld_save_inspector/service.py; parser/core.py and indexes.py only if a reproduced root cause requires them; tests/v1/test_semantic_consistency.py.

Consumes: Snapshot, QueryService.execute(QueryRequest), normative sections 3–5 and Appendix C. Produces: consistent core counts, domain collection states and map-scope availability with preserved schema shape.

Establish expectations from handwritten synthetic XML before observing product output. Pin a complete pawn to skills=1, traits=1, hediffs=1, endogenes=2, xenogenes=0, equipment=1, apparel=1, inventory=2. Test absent, explicit-null, invalid and empty variants; nested contents and duplicate references cannot inflate immediate counts. Add a direct-map fixture with unrelated null collections and verify the roster remains present and paged totals match its records. Preserve failing pytest logs; implement root causes; rerun the new regressions and existing affected suites. Commit a focused change only after green checks and self-review. Broader consequential contradictions go to lead.

## Task 2 — adversarial cross-interface acceptance coverage

Files: tests/v1/test_interface_consistency.py, tests/v1/test_lifecycle_consequences.py; adapters only for reproduced defects, with ownership assigned after Task 1.

Compare the shared Python response with installed CLI and real stdio MCP for omitted defaults, malformed arguments, duplicate and unresolved identities, nested-holder selectors, full pagination and stale cursors. Exercise cancellation, concurrency, failed-load recovery and pinned ready snapshots. Check downstream invariants: no fabricated totals, no dropped records, no double-counted references, no mixed-snapshot pages, no private path in default success/error/log outputs. Preserve red/green results and run relevant existing suites. Fixture assertions come from independently constructed XML, never implementation-derived snapshots.

## Task 3 — finalize normative contract

Files: docs/design.md, docs/rimworld-save-inspector/*.json, src/rimworld_save_inspector/schemas.py, tests/contract/ and verification case mappings.

Reconcile every required field, effective default, selector, population basis, collection state, compatibility claim and snapshot lifetime with the user objective. Record factual corrections and their independent evidence; do not revise expectations to accept a defective implementation. Separate publishable product contracts from private acceptance data without weakening the private acceptance gate. Validate all schemas and public examples, then test product responses against them. Reconcile gate case identities when adding meaningful tests.

## Task 4 — polish installable v1 and public CI

Files: README.md, CHANGELOG.md, LICENSE, pyproject.toml, uv.lock, src/rimworld_save_inspector/__init__.py, .github/workflows/ci.yml and examples/.

Set coherent 1.0.0 metadata. Provide CLI, Python and MCP installation/examples (including apparel and pagination), missing-data interpretation, compatibility, troubleshooting and limitations. Public CI must execute synthetic tests and build/install wheel and sdist outside the source checkout; private gates remain explicitly separate. Verify examples as real commands on synthetic files. Avoid adding private paths or extracted fixture facts to public material.

## Task 5 — final frozen packaged acceptance and independent review

Files: tools/verify.py and gate adapters only for reproducible harness defects; private evidence is ignored and immutable per attempt.

Freeze the candidate and build artifacts. Establish/verify independent oracles before comparing implementation. Run required G0–G7 with exact packaged candidate, complete public platform matrix, retained unique command logs and authenticated artifacts. A fresh reviewer must inspect code and independently reproduce consequential semantic, lifecycle, preservation and packaging results. Fix findings, refreeze and rerun affected gates; no skipped check counts as acceptance. Source or assumption changes invalidate affected evidence.

## Task 6 — audit and publish only the proven final state

Files: reproducible release audit scripts and public release documentation; private audit records remain outside publication.

Await explicit resolution of the confirmed exact-history/private-data contradiction before any rewrite/publication. Preserve an exact private Git bundle and verify restoration if sanitization is approved. Audit every publishable reachable commit/blob/ref plus wheel, sdist and release attachments; authenticate the final scan scope and review false positives. Use authenticated logan-crosby GitHub access to create the public repository only after the audit passes. Push audited history, tag v1.0.0, publish matching artifacts, wait for public CI and read back repository visibility, tag/commit, release assets and hashes. Public release is incomplete until these external results are verified. PyPI is not separately requested; a GitHub release with independently installable Python artifacts satisfies this publication target.

## Integration and verification ownership

Task 1 produces shared semantics consumed by Tasks 2–5. Task 2 tests interfaces consumed by Tasks 3–5. Tasks 3 and 4 share README/schema/version expectations and are integrated by lead before Task 5. Task 6 consumes the final frozen candidate and user history ruling; it cannot run on historical acceptance evidence. There are no concurrent overlapping edits. Beads issues link exact ownership, status and evidence. Obsidian records authorization, contradictions, failed approaches, current candidate and the next action.
