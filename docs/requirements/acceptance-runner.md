# Complete acceptance runner

Public CI exercises deterministic Python and C# suites, the pinned reference build, actual serializer interoperability, packaging and installed legacy examples. It has no access to private saves or licensed native runtime inputs and does not certify the full product.

The final local or secured-runner result is produced by:

```sh
python -m tools.aggregate_acceptance --bundle /private/evidence/bundle.json \
  --candidate /private/evidence/final-candidate.json \
  --registry docs/requirements/requirement-register.json
```

The candidate contains the final commit, source tree SHA256, wheel SHA256, sdist SHA256 and recorder SHA256. Generate `source_tree_sha256` with `tools.aggregate_acceptance.source_tree_fingerprint` from the clean, final checkout. It hashes a sorted JSON array of `[Git-tracked POSIX path, byte size, SHA256 of exact bytes]` rows. The validator verifies the current `HEAD`, requires a clean `git status --porcelain`, and recomputes that fingerprint. Commit and rerun affected gates after any tracked source change. The external candidate JSON must agree with the candidate in the bundle and every receipt.

The bundle's `packages` object must contain `wheel`, `sdist`, and `recorder` references, each with relative `path`, exact `bytes`, and `sha256`. The retained package bytes must match the corresponding candidate hash. Preserve build provenance and clean installed-package test evidence in the H6/H7/A7 producers; package hashes alone establish byte identity, not that the package was built from the stated source or exercised in a native runtime.

Every G0–G7, H0–H7, L0–L7 and A0–A7 receipt must name exactly that candidate. Retained command IDs, argv, environments, UTC intervals, exit codes, stdout/stderr and distinct passing JUnit identities per gate check are required. The per-check evidence kinds are fixed in `tools/gates/complete_contract.py`: actual native checks require `native_test`, benchmark checks require `performance`, and H7/L7/A7 final review checks require `independent_review`. A producer cannot relabel a native or benchmark result as a generic product test. Receipt and JUnit parsing consumes the same bytes that passed size and SHA256 authentication. Artifact files are opened through held directory descriptors with `O_NOFOLLOW`, so an ancestor symlink replacement cannot redirect a hash read outside the evidence root. Original G semantic validators remain mandatory; the G manifest must be an indexed artifact, identify the same gate and candidate, and pass the original validator.

The registry must match the independently frozen canonical JSON SHA256 in `tools/gates/complete_contract.py`. The separately frozen [acceptance proof map](acceptance-proof-map.json) names the specific semantic checks required for all 75 mandatory rows. Each requirement result must include those checks; a convenient first check from each named gate is insufficient. A fresh reviewer must inspect whether each mapped producer assertion actually proves the named behavior. In particular, `A5.source_channels` covers deterministic and semantic source channels (DISC-03); `A5.evidence_use_ledger` covers selected, rejected, missing, contradictory, and lower-ranked evidence (DISC-09); `A5.historical_artifact_links` covers source-linked historical artifacts (DISC-11); `A5.bounded_followups` covers follow-ups relevant to named uncertainty and sources with default 5 and hard maximum 20 (DISC-12); `A6.cache_invalidation` covers save/catalog generation, source channel, resolver, rubric, model, and prompt changes (DISC-13); and `A5.preinstallation_abstention` covers recommendations before installation (REC-P5). These IDs require distinct real producer assertions and fresh review; validator unit fixtures do not establish their product behavior.

The G1.T33 package producer must start after the final candidate commit. Its finish time is the package-ready boundary. Product, native, performance and review commands must start after both the commit and package-ready boundary; independent baseline-oracle commands may predate them. Every command interval must be ordered and no more than five minutes ahead of the validator clock. Product evidence reuse is disabled: final native, recorder performance, installed and review checks must run again against the final committed candidate and packages, even when relevant source bytes appear unchanged. The validator checks the source and package bytes again before returning a product result.

The A7 receipt must contain `independent_review` checks for installed behavior, native execution, chronology, preservation, faults, discovery and performance. The bundle must name a fresh reviewer distinct from its implementers after trimming and case folding identifiers. The validator authenticates evidence bytes and checks declared identities; reviewer independence, approval authorship, package build provenance and the meaning of test assertions still require external, fresh review.

Missing, skipped, failed, malformed, unauthenticated or stale evidence prevents `product_accepted=true`. Validator self-tests return `SELFTEST_PASS`, never product acceptance; the disposable positive product-path test stubs original G semantics and is only a validator oracle. Real private/native evidence and real inference remain separate gates until authorized and executed.

The section inventory in `tools/gates/complete_contract.py` is necessary coverage, not a substitute for semantic assertions or independent reproduction. Native/private producers must retain their raw evidence privately. Do not upload private save contents, colony details or game assemblies to public CI. Host registration and publication need separate authorization.
